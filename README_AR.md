# نظام إدارة الحضور والانصراف — الإصدار الثاني المُراجع

تطبيق مكتبي عربي لإدارة الموظفين والأقسام والورديات والحضور والانصراف والإجازات والتقارير، باستخدام Python وTkinter وSQLite.

## متطلبات التشغيل
- Python 3.11 أو أحدث مع Tkinter.
- المكتبات الخارجية في `requirements.txt` للتصدير إلى Excel وPDF.
- تم فحص الكود وتشغيل اختبار واجهات Tkinter على Python 3.13.5 في بيئة اختبار Linux. لم يتم التحقق بعد على جهاز Windows الخاص بالمستخدم أو على Python 3.14 تحديدًا.

## التشغيل
1. فك ضغط الملف كاملًا.
2. افتح مجلد `attendance_v2`.
3. ثبّت المتطلبات:
   `python -m pip install -r requirements.txt`
4. شغّل:
   `python main.py`
   أو على Windows شغّل `run.bat`.

## بيانات الدخول الأولية
- اسم المستخدم: `admin`
- كلمة المرور: `Admin@123`

غيّر كلمة المرور بعد أول دخول. تُخزّن كلمات المرور الجديدة باستخدام PBKDF2-HMAC-SHA256 مع Salt عشوائي. إذا وجد البرنامج كلمة مرور قديمة بصيغة SHA-256، فإنه يرقّي تخزينها إلى PBKDF2 بعد تسجيل دخول ناجح.

## الوظائف التي تم تحسينها في هذه النسخة
- عدم إعادة إنشاء حساب المدير أو إعادة تعيين كلمة مروره عند كل تشغيل.
- ترقية كلمات المرور القديمة بعد التحقق منها.
- إدارة المستخدمين: إنشاء وتعديل وتعطيل الحسابات وتحديد الدور (مدير/مسؤول/مستخدم).
- إظهار عناصر القائمة والاختصارات بحسب الدور؛ المدير وحده يرى إعدادات أيام العمل والمستخدمين وسجل العمليات والنسخ الاحتياطي.
- ربط تقارير الغياب بأيام العمل الأسبوعية والعطلات الرسمية، مع مراعاة تاريخ التعيين.
- استثناء العطلات وأيام الراحة من حالة الغياب في سجل اليوم.
- اختيار الوردية عند تسجيل الحضور، ودعم أكثر من سجل في اليوم إذا كانت السجلات مرتبطة بورديات مختلفة.
- عرض سجلات الورديات المتعددة منفصلة في السجل اليومي وإتاحة تعديل سجل بعينه.
- حساب التأخير والخروج المبكر والساعات الإضافية وساعات العمل في السجل والتقرير الشهري.
- معالجة الورديات الليلية التي تنتهي في اليوم التالي عند حساب المدة والخروج المبكر والإضافي.
- منع تداخل طلبات الإجازات غير المرفوضة، وإصلاح تحديد الموظف عند تعديل الطلب.
- تعطيل الموظف بدل حذف سجلاته التاريخية، للمحافظة على الحضور والإجازات المرتبطة به.
- إضافة حذف الورديات مع منع حذف الوردية المرتبطة بموظفين أو سجلات.
- إظهار عدد الغياب وسجلات الانصراف غير المسجل في لوحة التحكم.
- إصلاح خطأ هندسي في واجهة إدارة الأقسام كان يمنع فتحها.
- تسجيل أحداث إضافية في سجل العمليات.

## قاعدة البيانات
تُنشأ `attendance.db` تلقائيًا بجانب `main.py`. لا تحذف هذا الملف إذا كنت تريد الاحتفاظ ببياناتك. خذ نسخة احتياطية قبل أي تحديث أو استعادة.

## النسخ الاحتياطي والاستعادة
من القائمة الجانبية افتح «النسخ الاحتياطي». أنشئ نسخة قبل الاستعادة. الاستعادة تتحقق من `PRAGMA integrity_check` وتطلب تأكيدًا، ثم تتطلب إعادة تشغيل البرنامج.

## ملاحظات مهمة
- عند تسجيل حضور، اختر الوردية المناسبة. يجب أن تكون للموظف وردية افتراضية أو أن تختار وردية من القائمة.
- تسجيل الانصراف يبحث عن سجل حضور مفتوح للموظف في اليوم الحالي أو السابق؛ لذلك يدعم الوردية الليلية.
- يمكن تصحيح وقت الانصراف المفقود من «سجل الحضور اليومي» عبر تحديد السجل ثم «تعديل السجل المحدد».
- في شاشة «إدارة الموظفين» استخدم زر «حفظ موظف جديد» لإضافة موظف.
- لتعديل موظف: حدده من الجدول (أو انقر عليه مرتين)، عدّل الاسم أو الرقم الوظيفي أو بقية الحقول، ثم اضغط «تعديل الموظف المحدد».
- لحذف موظف: حدده من الجدول ثم اضغط «حذف الموظف المحدد». سيطلب النظام تأكيدًا نهائيًا، وسيحذف سجلات حضوره وطلباته المرتبطة أيضًا؛ لا يمكن التراجع عن الحذف.
- زر «تفريغ الحقول / موظف جديد» يلغي تحديد الموظف ويجهز النموذج لإضافة موظف جديد.
- الأدوار الحالية تطبق تقييد الوصول على القوائم والاختصارات داخل التطبيق. إذا كان النظام سيُستخدم في بيئة إنتاجية متعددة المستخدمين، فيلزم توسيع التحقق من الصلاحيات على مستوى كل عملية خدمة/قاعدة بيانات.
- لم تُضف حتى الآن بطاقة موظف مستقلة، ولا سجل تدقيق شامل لكل تغيير في كل شاشة، ولا آلية حضور ذاتية للموظفين.
- لم يتم تنفيذ اختبار يدوي على جهاز Windows الفعلي. اختبار إنشاء الواجهات لا يثبت وحده أن كل تفاعل مستخدم أو طباعة أو تصدير يعمل على كل جهاز.
